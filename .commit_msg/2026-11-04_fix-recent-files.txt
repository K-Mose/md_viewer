fix: 최근 파일 다시 열기 개선 및 file_picker 12.3 API 대응

최근 파일 목록이 실제 원본을 가리키도록 바꾸고, 파일을 열지 못한
이유에 따라 다르게 처리하도록 수정한다.

버그 수정
- UTF-8이 아닌 파일을 "삭제됨"으로 처리해 최근 목록에서 지우던 문제
  - 파일을 바이트로 읽고 UTF-8 → CP949(EUC-KR) → 깨진 글자 허용 순으로 디코딩
  - UTF-8 BOM 제거
  - 파일이 없거나 권한이 없을 때만 목록에서 삭제하고, 그 밖의 오류는 유지
- file_picker 캐시 사본 경로가 저장되던 문제
  - Android: ACTION_OPEN_DOCUMENT + 영구 읽기 권한(content:// URI)
  - iOS: UIDocumentPicker(asCopy: false) + security-scoped bookmark
  - Windows 등 데스크톱: file_picker가 주는 실제 경로
  - 목록 위치 표시를 "Download/a.md", "iCloud Drive/..." 형태로 정리
- 외부 앱 "연결 프로그램"으로 연 파일이 최근 목록에 남지 않던 문제
  - Android: 영구 권한을 받을 수 있으면 URI, 아니면 앱 내부 사본으로 저장
  - iOS: LSSupportsOpeningDocumentsInPlace로 원본 위치에서 열고 북마크 저장
- file_picker 12.3에서 pickFiles()가 List<PlatformFile>을 돌려주도록
  바뀌어 Windows 빌드가 실패하던 문제 (.files → firstOrNull)

변경 사항
- lib/services/document_service.dart 추가: 플랫폼별 선택/다시 열기,
  오류 종류(notFound / permissionDenied / unknown)
- lib/services/text_decoder.dart 추가: 인코딩 판별/디코딩
- lib/services/recent_files.dart: RecentFile에 ref{kind, value}, location 추가,
  이전 저장 포맷 호환, 목록에서 밀려난 항목 반환(권한/사본 정리용)
- lib/services/opened_file_service.dart: Android/iOS 모두 MethodChannel 사용
- lib/screens/home_screen.dart: 열기 흐름 통합, 오류별 안내 메시지
- MainActivity.kt: md_viewer/documents 채널, 백그라운드 읽기
- AppDelegate.swift(DocumentsBridge), SceneDelegate.swift: 파일 URL 직접 처리
- Info.plist: LSSupportsOpeningDocumentsInPlace 추가
- 의존성: cp949_codec 추가, app_links 제거
- test/services_test.dart 추가: 디코딩, 최근 목록 마이그레이션/중복/밀려남
